## V9：如何調整排程

1. 開啟「排程管理」，查看資料來源、排程狀態、已保存版本及時間。
2. 調整每日採集／報表時間，或明天起的日期、分類、關鍵字、最多商品數。新增列全部留空即忽略；刪除未來安排須清空該列四個欄位。
3. 按「預覽變更與用量」。畫面比較變更前後時間、計畫剩餘請求、排隊預留、本機剩餘與套用後完整安排。
4. 確認符合需求後按「確認套用排程設定」。每次確認只新增一個版本，重複送出相同確認不會另存或重新採集。
5. 返回營運總覽，核對 Python 的近期回報與已採用版本。保存成功不等於程序已讀取，更不等於採集成功。

時間與商品安排從明天生效，今天及過去安排不更改。暫停／啟用狀態立即生效，排程器在下一次檢查採用；正常檢查間隔 10 秒。若有工作正在執行，套用會拒絕，需等該工作完成再重新預覽。

暫停會停止排程中的採集與每日報表，仍保留未來計畫用量；不取消另行確認的手動任務。跨日暫停後，已經過採集時間且確實處於暫停的日期，會在恢復預覽中列為「因暫停跳過，不補抓」，並保存於版本。其他漏跑／失敗不會被當作暫停，也不會自動補抓。

### 試點限制

- 同一有限期計畫、每日一批，日期遞增且不得重複；總批數最多 30，首末日期相隔最多 30 天。
- 每批最多 1–2 件。真實來源預估為 1 次搜尋 + 每件 1 次明細；兩件最多 3 次，不是兩次。
- 時區固定台灣，採集不得早於 09:00，報表必須晚於採集。
- 啟用前檢查已用額度、排隊預留及全部剩餘計畫；免費方案／供應商最近觀測缺失、漏跑或來源核對有問題時不允許啟用。
- 本機上限維持此 DB 累計 30 次、每日 5 次，UTC 日在台灣 08:00 重置。修改排程不會重設帳本，也不會提高限額。
- 供應商數字是這把金鑰最近回應的保守估計，有觀測時間；不是 RapidAPI 帳號即時餘額。其他應用使用相同金鑰可能使估計過時。
- 無依剩餘額度自動擴量、無歷史補抓、無失敗自動重試。長期多計畫管理仍是後續工作。

目前真實計畫保持 2026-10-04～10-08，採集 10:00、報表 10:10。開發驗證未替真實計畫保存新版本。10-07 數位扭力扳手、10-08 鐵皮剪仍待實際到期執行；若未新增經確認的未來安排，10-08 後不繼續採集。

### 設定保存方式

網站將每次確認保存到 `schedule_versions`，包括原設定雜湊、完整計畫、啟用狀態、時間、生效日與確認時間。原計畫及 `python-scheduler.json` 不覆寫；Python 每次檢查讀取已核准版本，時間只採用當日已生效的版本。

原設定及計畫仍固定雜湊。直接修改這些基礎檔會停止程序或拒絕讀取，不能用改檔繞過預覽。換電腦時需搬移一致 DB 備份、原設定與原計畫，才能保留網站已保存的版本與帳本。不要刪除版本表或排程工作狀態來重試。

## V10：如何產生每期報表

1. 在「報表中心」選來源、台灣開始／結束日期、分類、品牌或商品名稱／ASIN，以及統計方式。
2. 按「查詢並固定資料範圍」，查看成功批次、商品數、價格、累計評價數及商品明細。畫面最多顯示 20 件，匯出包含該範圍全部符合商品。
3. 按「預覽並保存本期 Excel」，核對同一範圍、分頁及 API 0 次。
4. 按「確認保存新版本」。背景工作完成並讀回核對後，版本頁開放 Excel 下載；執行中每 5 秒更新。
5. 版本頁也可下載同範圍商品／統計 CSV，或預覽相同範圍重產。重產另建版本，原檔保留。

日期以成功批次完成的台灣日期判斷，含結束當日；同一市場／ASIN 先取該期間內最新一筆，再套用分類、品牌與價格等條件。相同商品跨批次不會重複加總累計評價數；不能用分類篩選找回已被較新觀測取代的舊商品。

保存時固定成功批次清單、網站來源核對截止版本、完整查詢條件與來源／商品資料摘要。後續新採集不會混入舊版本。若原來源或入庫資料被更改，重新產報與 CSV 會拒絕，提示重新查詢；已產原檔仍保留，下載需通過檔案完整性核對。

### Excel 分頁

| 分頁 | 內容 |
| --- | --- |
| 報表說明 | 來源、期間、固定批次、查詢條件、商品數、均價、資料定義及匯出用量 |
| 取樣統計 | 分類／品牌 × 價格帶、商品數、有值商品數、均價、已知累計評價數、留存評論樣本數、來源覆蓋 |
| 商品明細 | 實際選用的批次、ASIN、分類、標題、品牌、價格、評分、評價數、採集時間、來源證據與評論樣本數 |
| 批次來源 | 固定範圍內各成功批次的分類、關鍵字、市場、完成時間及本報表實際採用件數 |

四頁均有實際儲存格框線、文字換行、凍結表頭；資料頁有篩選。價格與計數保存為數值，來源文字拒絕當作公式，缺值不補成零。匯出後逐列讀回核對，未通過便不提供已驗證下載。

此報表是新的固定期間格式（資料表版本 4）。原每日報表是累計來源分類活頁簿（15 頁），保留檔案與格式，在報表中心另列「原每日與累計報表」。兩者資料範圍不同，不能直接當作同一期數字比較。

報表中心列出該來源最近 100 份期間版本；較早版本保留於 DB 與磁碟，可由已知版本網址查閱，不會被改標成累計報表。目前沒有完整分頁搜尋介面。

### 評論及來源的界線

「評價數」沿用來源提供的累計數；不是本期新增評論數，也不保證不同 ASIN 的評價數互不共享。「評論樣本」是供應商明細已提供且留存的內容，不是完整評論集合。不新增人工／AI 情緒或主題判斷。評論原文與來源查驗仍從商品的來源入口查看，完整評論擷取及原 sample 八種報表尚未完成。

真實月銷量、總銷售金額仍未取得。不能用價格乘評價數推成銷售金額，也不能把有限取樣當全市場排名。

## 安全與上線界線

新增寫入只在本機模式提供，沿用既有 API 驗證。寫入必須是本機且同來源表單；工作階段綁定、HMAC 簽章、五分鐘有效期限、請求大小限制、重複欄位拒絕及鎖內重新核對維持啟用。確認內容改變、程序重啟或條件變動時需重新預覽。既有 token 不回傳到新畫面，也不寫入報表。

V10 完成的是本機功能驗收。尚未部署雲端正式網站，也未實作多人登入／角色權限、集中秘密管理、24 小時可用性或定時異地備份。Windows／Linux 實機常駐仍待驗證；明日真實採集須等實際到期結果，不能把模擬排程測試當成功採集。

下一階段建議先驗證 10-07／10-08 的實際 Python 採集及報表，再做跨機備份還原與長期多計畫管理。免費額度確認前不擴大擷取；多人或雲端部署前再確定資料敏感度與地緣限制。
