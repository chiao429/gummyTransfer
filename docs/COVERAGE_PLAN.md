## 來源欄位稽核與下一批驗收

2026-10-04 離線檢查已留存的來源證據：run_id=5、6、7 共 5 筆商品均留有品牌與顏色欄位，只有 2 筆留有材質；5 筆都沒有留存公／英制、尺寸的結構化欄位。run_id=3 的 2 筆舊商品沒有來源證據，不能回推供應商當時給了哪些欄位。這些既有批次採集時只保存參與映射的選定欄位，因此「未留存」也不能推論供應商完整回應一定沒有其他規格。後續新批次會額外有限度保存商品屬性的欄名與短文字值，供離線評估新映射；它們仍標成未分類，若有值會列在累計 Excel 的「來源附加欄位」頁，不會自動寫入規格組合。標題中的 Metric、SAE 或尺寸只可列為待查候選。

[供應商商品明細範例](https://www.openwebninja.com/api/real-time-amazon-data) 顯示 `product_information`／`product_details` 的欄名依商品而異，明細的 `sales_volume` 可以是空值；搜尋範例則可能是「1K+ bought in past month」這類概略文字。後續新批次若在已請求的搜尋結果或商品明細中取得這類短文字，系統會分開留存來源並列在「來源附加欄位」，但只稱為**購買提示**，不能當成原表的 `sum_sales` 或月銷售金額。舊批次沒有留存，不能回推。供應商範例中的 Best Sellers Rank 也不能在未確認原表定義前映射成 `score_rank`。此調整沒有新增 API 請求或猜測的數值欄位。
